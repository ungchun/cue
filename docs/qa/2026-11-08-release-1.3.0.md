### R-07 상세 시트 수정 반영 — FAIL (2/2 재현)
- 재현: + 시트로 할일 저장 → 바로 일정 칩 → 수정 → 제목 바꿔 저장
- 기대: 시트가 닫히면 월 캘린더 칩이 새 제목
- 실제: 저장소엔 새 제목·하루 종일이 반영(CalendarItem `QA 월간 수정|1`)됐는데, 20초 넘게 월·타임라인 모두 옛 제목.
  달 이동·탭 전환으로도 안 바뀌고, 앱 재실행하면 새 제목
- 할일 저장을 사이에 두지 않은 수정 2회(제목만, 제목+하루 종일)는 0.38~0.39s에 정상 반영 → 조건은 “할일 저장 직후”
- 원인: 시트는 `ScheduleView`의 `EKEventStore`로 쓰고, 화면은 `EventKitEventsRepository`의 장수명 `EKEventStore`로 읽는다.
  할일 저장 직후 일정 저장엔 EventKit이 변경 알림을 빠뜨리는데(30b0aa7), 그러면 저장소 쪽 store가 캐시한 옛 이벤트를
  계속 돌려준다. 30b0aa7의 “직접 재조회”는 새 일정(캐시에 없음)만 살렸고 기존 일정 수정은 같은 캐시를 다시 읽어 그대로다
- 수정(a190728): `EventsRepository.discardCache()` 추가(EventKit 구현은 `store.reset()`), `ScheduleViewModel.reloadAfterOwnWrite`가
  다시 읽기 전에 부른다. 월 캘린더도 같은 저장소를 읽어 함께 풀린다. 테스트: 캐시를 흉내 낸 더블로 타임라인·월 둘 다 새 제목을 읽는지
- 재검증: 사용자 빌드 대기 — 같은 순서(할일 생성 → 일정 수정)로 R-05~R-07 다시

## 체크리스트 — Duo

### D-01 메모 입력줄 (펼침) — 수정 전 FAIL → 수정 후 PASS
- 전제: 메모 탭, 입력 비어 있음. Duo 펼침.
- 수정 전: 밑줄이 콘텐츠 폭 거의 전체(약 860pt)로 늘어났다. 라이브 버튼이 오른쪽 탭바 바로 옆까지 밀려 입력줄 가운데에서 멀어졌다. → `assets/2026-11-23-duo-ui/before-open-memo.png`
- 수정 후: 입력 TextView는 x 229, 폭 409. 라이브 버튼은 x 558, 폭 116이라 오른쪽 끝이 674다. 블록은 193–674로 폭 약 480이고, 콘텐츠 영역(871pt) 가운데에 놓인다. → `after-open-memo.png`

### D-02 메모 긴 입력 (펼침·접힘) — PASS
- 조작: 영어 긴 문장을 입력했다. 시뮬레이터 키보드가 한글 입력 모드라 몇 글자가 섞였지만 판정과는 관계없다.
- 펼침: 480 안에서 2줄로 줄바꿈되고 가운데 정렬이다. 지우기(x)와 라이브 버튼은 블록 오른쪽 끝에 붙는다. → `after-open-memo-text.png`
- 접힘: 3줄로 넘어가면 왼쪽 정렬로 바뀐다. 이는 `GrowingTextView.swift:144`의 기존 동작(3줄 초과 → `.natural`)이며 이번 변경과 관계없다.
- 확인 후 지우기(x)로 입력을 비웠다(TextView value = 빈 값).

### D-03 온보딩 1·2장 버튼·문구 (펼침) — 수정 전 FAIL → 수정 후 PASS
- 수정 전: "계속" 버튼이 x 24에서 오른쪽 탭바 영역 앞까지 약 860pt로 늘어나, 가운데 일러스트·문구와 축이 맞지 않았다. → `before-open-onb1.png`, `before-open-onb2.png`
- 수정 후: "계속" 버튼은 x 193, 폭 481로 일러스트·문구와 같은 축에 가운데 정렬된다. 제목(폭 211)과 본문(폭 279)은 원래 짧아 위치가 그대로다. → `after-open-onb1.png`, `after-open-onb2.png`

### D-04 온보딩 3장 "잠금화면에 띄우기" (펼침, 키보드 위) — 수정 전 FAIL → 수정 후 PASS
- 수정 전: 키보드 위 버튼이 약 860pt로 늘어났다. 입력칸(최대 240)과 질문만 가운데에 놓여 위아래 축이 어긋났다. → `before-open-onb3.png`
- 수정 후: 버튼 폭이 480으로 줄어 입력칸·질문과 같은 축에 놓인다. → `after-open-onb3.png`

### D-05 접힘 상태 (466×678) — PASS
- 온보딩 1장 "계속"은 x 24, 폭 334, y 577이고, 3장 "잠금화면에 띄우기"는 x 24, 폭 334다. 둘 다 수정 전과 같다. 콘텐츠 폭(382 − 48 = 334)이 상한보다 좁기 때문이다.
- 메모 TextView는 x 60, 폭 262이고 라이브 버튼은 x 243이다. 수정 전과 배치가 같다.

### D-06 손대지 않은 화면 (접힘·펼침) — PASS
- 일정(월 달력·타임라인), 할일, 집중, 설정, 일정 편집 시트, 페이월을 수정 전 빌드로 접힘·펼침 모두 확인했다.
- `List`·`Form` 화면은 시스템 여백을 따르고, 시트는 펼침에서 가운데 폼시트로 뜬다. 고칠 곳이 없었다.
- 이 화면들의 코드는 바꾸지 않았다. `ContentWidth`를 쓰는 곳은 위 3곳뿐이다(R-03).

### D-07 집중 실행 중 화면 — SKIP
- 이유: 시뮬레이터에서 AlarmKit 시작이 진행되지 않아 실행 중 상태를 만들 수 없었다. 대기 화면은 D-06에서 확인했다.
- 수동 확인: 실기기 Duo가 생기면 집중을 시작한 뒤 펼침 화면을 본다.

## 종합

Duo 접힘(커버 디스플레이)은 일반 iPhone보다 좁고 낮은 세로 화면이라 원래도 문제가 없었다.
문제는 펼침(가로 약 950pt)에서 **가운데 정렬 커스텀 레이아웃이 `maxWidth: .infinity`로 화면 끝까지 늘어나는 것** 하나로 모인다. 메모와 온보딩만 해당되고, 나머지 화면은 시스템 컴포넌트(`List`/`Form`/시트)라 시스템이 알아서 처리했다.
앞으로 가운데 정렬 커스텀 레이아웃을 새로 만들면 `ContentWidth.readable`을 함께 건다(`docs/design-system.md`).

## 2차 — 전 화면 직접 점검 (2026-11-24, 중단)

1차 D-06은 화면을 훑어본 수준이라, 화면마다 접힘·펼침을 나란히 찍어 다시 보다가 사용자 요청으로 중단했다.

### 수정 — 빠르게 접고 펴면 월 달력이 2016년으로 튐
- 증상: 월 달력을 보다가 Duo를 0.3초 간격으로 펴고 접으면 보던 달이 2016년 11월(−120달)로 바뀐다. 일반 속도로는 0/6, 빠른 연속에서는 바로 재현됐다.
- 원인: 페이지 `TabView`는 폭이 연달아 바뀌면 스크롤 위치를 잃고 첫 페이지로 간 뒤, 그 값을 선택 바인딩에 다시 써 버린다.
- 수정: `ScheduleMonthView.swift`의 `pager`를 `GeometryReader`로 감싸고, 폭이 바뀌면 `.id(proxy.size.width)`로 TabView를 새로 만든다. 새로 만든 TabView는 선택한 페이지에서 시작한다. 세로 고정 iPhone은 폭이 바뀌지 않아 동작이 그대로다.
- 재검증(Duo): 같은 빠른 연속·중간 자세(0.5)·애니메이션 없음 순서를 3회 돌렸고 튐은 0회였다. 다른 달을 보고 있을 때도 그 달이 유지됐다.

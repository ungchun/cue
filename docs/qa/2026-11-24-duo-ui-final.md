## 수정

### F-1 커버 화면 + 키보드에서 폐기 확인 제목 잘림 (접힘) — 수정 전 FAIL → PASS
- 재현: 접힘 → 할일 → 목록 정보 보기 → 이름 한 글자 입력 → "…" → 닫기.
- 원인: 커버 화면은 툴바가 오른쪽 세로줄에 놓이고, 키보드가 올라오면 ✕·✓가 "…" 넘침 메뉴로 접힌다.
  거기서 뜬 popover가 키보드 위 공간에 눌려 h137 → h101이 되고, 제목(y253)이 popover 위(y264) 밖으로 잘렸다.
- 수정: ✕에서 폐기 확인을 띄우기 전에 키보드를 내린다(`dismissKeyboard()`, 할일 상세·일정 상세·목록 편집 3곳).
- 후: popover h137, 제목 y288로 안쪽. → `before-fold-discard-kb.png` / `after-fold-discard-kb.png`

### F-2 상세 시트 ✕가 넘침 메뉴에서 빠짐 (접힘) — 수정 전 FAIL → PASS
- 같은 상황에서 할일 상세 시트의 "…" 메뉴에는 "저장"만 있어, 키보드를 내리기 전엔 시트를 닫을 수 없었다.
- 원인: ✕ 라벨이 제목 없는 `Image`였다. 넘침 메뉴는 제목 없는 버튼을 빼 버린다(목록 편집 시트는 `Label`이라 정상).
- 수정: 할일·일정 상세 시트의 ✕를 `Label("Close", systemImage: "xmark").labelStyle(.iconOnly)`로. 메뉴에 닫기·저장 둘 다 뜬다.

### F-3 할일 상세를 닫고 탭을 오가면 키보드 부활 (Duo 무관) — 수정 전 FAIL → PASS
- 재현: 할일 행 제목 탭(인라인 편집) → ⓘ → 닫기 → 일정 탭 → 할일 탭. 키보드가 뜨지만 행은 편집 상태가 아니다.
- 원인: 행의 `GrowingTextView`는 항상 mount돼 있고 become만 한다. `openDetailSheet`가 포커스 값만 꺼서
  UITextView가 first responder로 남았고, UIKit이 탭 복귀 때 되살렸다.
- 수정: `openDetailSheet`에서 시트를 열기 전에 `dismissKeyboard()`. 수정 전 빌드로 같은 순서를 돌려 재현, 수정 후 재현 안 됨.
  새 입력 행 ⓘ 경로는 원래 정상.

### F-4 세션 색 칸 9+1 · 긴 세션 이름 (펼침) — 수정 전 FAIL → PASS
- 색 칸: `GridItem(.adaptive(minimum: 48))`이 폼시트 폭 621에서 9열이 돼 무지개(커스텀) 칸만 둘째 줄에 남았다.
  5열 고정으로 바꿔 5+5(목록 편집 6열과 같은 방식). → `before-open-session-colors.png` / `after-open-session-colors.png`
- 제목: 긴 세션 이름이 x92 w683으로 늘어났다. `ContentWidth.readable` 상한 → x201 w465, 링과 같은 중심, 끝은 "…".
- iPhone 18 Pro: 색 칸 10개 rect가 수정 전 빌드와 같다(예: 빨강 x46 y311, 커스텀 x323 y359). 제목은 원래 480보다 좁다.

### 관찰 (고치지 않음)
- 할일 칩 바(펼침): 액세서리 x50 w775, 칩은 x50–416에 왼쪽 정렬, 오른쪽 약 409pt가 빈다. 폭은 시스템
  `tabViewBottomAccessory`가 정한다. **유지**한다 — 가운데 정렬(`.defaultScrollAnchor(.center, for: .alignment)`)은
  목록 수에 따라 칩 위치가 움직이고 iPhone도 바뀐다. → `open-chipbar.png`
- 할일 행(펼침): 긴 제목이 한 줄 약 640pt, 짧은 제목과 ⓘ 사이 약 620pt. 시스템 `List` 행이라 둔다(미리 알림 앱과 같은 배치).
- 설정 Premium 배너·메모 라이브 미리보기 카드(펼침): List 행 폭 847을 따른다. 카드는 실제 잠금화면보다 넓다 — 아래 안내 문구가 있어 둔다.

- 새 목록 시트는 열면서 키보드가 올라와 둘째 색 줄을 가린다(접힘·펼침·iPhone 같은 동작).

  pager 영역 픽셀 차이 0.

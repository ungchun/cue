# 워크플로우 — refactor (리팩토링)

기능을 바꾸지 않고 구조·품질만 개선한다. `커버리지 확보 → refactor → green`.

## 순서

1. **범위 + "기능 불변" 선언** — 무엇을 정리하는지, 동작은 안 바뀜을 명시한다.
2. **커버리지 확보** — 대상 코드의 현재 동작을 포착하는 테스트가 있는지 확인한다.
   없으면 **characterization 테스트**(현 동작을 그대로 박는 테스트)를 먼저 추가한다.
3. **refactor** — 아래 체크리스트를 따라 **작은 단위로** 변경한다.
4. **green** — 각 작은 변경 직후 전체 테스트를 돌린다.

## refactor 체크리스트

에이전트는 리팩토링을 건너뛰거나 추상적으로만 하기 쉽다. 구체적으로 확인한다:

- [ ] 중복된 코드 블록을 함수/타입으로 추출했나
- [ ] 이름이 역할을 정확히 드러내나 (모호한 `data`, `info`, `manager` 제거)
- [ ] 함수가 한 가지 일만 하나 (너무 길면 분리)
- [ ] 매직 넘버·문자열을 상수로 뺐나
- [ ] 뷰에 raw 값이 직접 들어가 있지 않나 → [design-system.md](../design-system.md)
- [ ] 계층 경계를 넘는 의존성이 없나 → [ARCHITECTURE.md](../../ARCHITECTURE.md)
- [ ] 죽은 코드(안 쓰는 함수·타입)를 제거했나

## 커밋

리팩토링은 기능 추가와 **분리**해 커밋한다. 메시지 접두: `refactor:`

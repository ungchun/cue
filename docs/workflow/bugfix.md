# 워크플로우 — 버그 수정

[TDD 사이클의 버그 변형](../tdd.md#버그-수정-변형)을 따른다: `red → refactor → verify`.

## 순서

1. **재현 조건 정의** — "X 상황에서 현재 Y가 되는데, Z여야 한다"를 한 줄로 적는다.
2. **red** — 그 버그를 재현하는 **실패 테스트**를 먼저 작성한다.
   - 테스트가 처음부터 통과하면 → 버그를 잘못 짚은 것. 재현 조건을 다시 본다.
3. **refactor** — 버그가 있던 코드와 주변 설계를 개선한다. 이 과정에서 버그가 고쳐진다.
   - 빠른 땜질(quick patch)은 피한다. 버그는 설계 문제의 증상인 경우가 많다.
4. **verify** — 전체 테스트를 돌려 회귀 0건 확인.

## 커밋

버그 수정은 별도 커밋으로. 메시지 접두: `fix:`

## 왜 이렇게

한 번 잡힌 버그가 다시 나타나는 것(regression)을 근본적으로 막기 위해서다.
재현 테스트는 그 버그를 영구히 고정하고, 주변 품질 개선은 근본 원인을 완화한다.

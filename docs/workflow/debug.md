# 워크플로우 — debug (원인 진단)

원인을 모르는 문제의 **근본 원인을 찾는다. 고치지 않는다.**

debug는 독립 모드이자, feat · fix · refactor 어디서든 호출되는 **진단 서브루틴**이다.
다른 모드가 예상 밖 실패를 만나면 debug를 호출하고, 끝나면 원래 모드로 복귀한다.

## 순서

1. **재현** — 반복 가능한 실패를 먼저 확보한다. 재현되지 않으면 진단할 수 없다.
2. **가설 → 검증** — 가설을 세우고 좁혀 간다 (이분 탐색, 로그, 격리).
   추측만으로 코드를 바꾸지 않는다.
3. **산출** — 두 가지를 만든다:
   - ① **재현하는 실패 테스트** (= TDD의 red)
   - ② **근본 원인 진단** — 무엇이 · 왜 · 어디서.
4. **멈춤** — 여기서 끝낸다. 고치는 것은 [fix](fix.md)의 일이다.

## 인계

- 독립 호출이었다면 → 진단을 사용자에게 보고하고, fix로 이어갈지 묻는다.
- 다른 모드의 서브루틴이었다면 → 원인을 들고 중단했던 모드로 복귀한다.

debug는 단독 커밋을 만들지 않는다 (수정이 없으므로). 산출한 red 테스트는 fix 커밋에 포함된다.
